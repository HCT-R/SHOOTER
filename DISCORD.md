# Pixel Protocol в Discord Activities

## Развёртывание

1. Установите Node.js 22+, выполните `npm ci` и `npm start`.
2. В [Discord Developer Portal](https://discord.com/developers/applications) создайте приложение и включите Activities. Для локального испытания включите Developer Mode в Discord.
3. Скопируйте `.env.example` в `.env`. Задайте `DISCORD_CLIENT_ID` и `DISCORD_CLIENT_SECRET`. Секрет используется только сервером и не включается в HTML или сборку SDK.
4. В OAuth2 приложения добавьте Redirect URI `https://127.0.0.1`, согласно руководству Activities. Приложение запрашивает только `identify`.
5. Разместите сервер за HTTPS с поддержкой WebSocket Upgrade; готовая схема Docker + Caddy описана в [DEPLOY.md](DEPLOY.md). В Activities → URL Mappings задайте префикс `/` и домен сервера без `https://`. HTML, `/discord.js`, `/api/*` и `/rooms` должны попадать в одно приложение.
6. Перезапустите сервер и запустите Activity из Discord. После обмена кодом и подтверждения личности меню показывает «DISCORD ACTIVITY · ПОДКЛЮЧЕНО».

Точный порядок настройки описан в [Building an Activity](https://docs.discord.com/developers/activities/building-an-activity). WebSocket поддерживается через proxy mapping; ограничения транспорта — в [Networking](https://docs.discord.com/developers/activities/development-guides/networking).

## Авторизация и транспорт

SDK выполняет `ready()`, затем `authorize()`. Код отправляется на `/api/auth/discord`. Сервер обменивает его на OAuth-токен и запрашивает `/users/@me`; позывной и подтверждённый Discord ID берутся из ответа Discord. Самостоятельно присланный клиентом ID не является доказательством личности. Сервер выдаёт отдельный непрозрачный токен игровой сессии; SDK получает OAuth-токен для `authenticate()`.

В обычном браузере `/api/session` выдаёт гостевую сессию. `REQUIRE_DISCORD_AUTH=1` отключает гостевой вход для развёртывания только в Discord. Офлайн-кампания и тренировки не требуют авторизации.

Клиент подключается к `/rooms` по WebSocket через текущий origin, передавая токен и версию протокола. Состояние боя рассчитывается на сервере 60 раз в секунду. Персональные снимки отправляются 20 раз в секунду. Клиент предсказывает своё движение и интерполирует видимых участников.

Пауза браузера не останавливает сервер. Выход создателя передаёт управление лобби другому участнику; активный FFA продолжается. Разрыв соединения оставляет уязвимого персонажа на карте. Повторное подключение той же сессии восстанавливает участника в пределах 30 секунд.

Комнаты, сессии и матчи хранятся в памяти. Перезапуск серверного процесса завершает их. Пул рабочих потоков распределяет симуляции комнат; `ROOM_CAPACITY` и `MAX_ROOMS` задают пределы развёртывания. Текущая основная цель — 32 участника на комнату.

## Живая приёмка

Браузерные тесты и подменённые ответы OAuth не заменяют проверку приложения в настоящем Discord. После настройки приложения нужны два реальных участника:

- вход и подтверждение личности, общий код комнаты и готовность;
- бой во всех трёх режимах, звук после первого жеста, клавиатура/мышь и геймпад;
- сворачивание окна, потеря сети, восстановление и выход создателя;
- наблюдение, результаты и реванш в той же комнате.

Сенсорное управление не является целевой платформой этой версии. Публичное распространение остаётся отдельным этапом: [Enabling Discovery](https://docs.discord.com/developers/discovery/enabling-discovery).
